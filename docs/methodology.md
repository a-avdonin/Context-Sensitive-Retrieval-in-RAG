# Методика

Исследование проверяет, сколько качества можно выиграть выбором стратегии для каждого хода (RQ1), помогает ли история самому роутеру (RQ2) и как меняются качество и стоимость (RQ3). [Результаты](../README.md) · [Воспроизведение](reproduction.md)

## Данные

Используются четыре общих корпуса IBM: Википедия (ClapNQ), документация IBM Cloud, финансовый форум FiQA и сайты госорганов США (Govt). Поиск и генерацию оцениваем на ходах с разметкой релевантности пассажей (qrels), относящихся к категориям ANSWERABLE и PARTIAL. Единица оценки — один вопрос пользователя с предшествующим диалогом.

| Датасет | Ходов в четырёх доменах | С qrels | Последующих с qrels |
|---|---:|---:|---:|
| MTRAG | 842 | 777 | 675 |
| MTRAG-UN | 507 | 332 | 309 |

Основной срез `later_turns` начинается со второго вопроса пользователя. На MTRAG 675 ходов относятся к 110 диалогам. На MTRAG-UN выбран один репрезентативный ход из диалога. Для переноса Adaptive-RAG после исключения пересекающихся диалогов остаются 303 задачи, включая 283 последующих хода. [Загрузчик и фильтр пересечений](../src/arag/data.py)

## Стратегии

Имя прогона имеет вид `<запрос>:<ретривер>[+rerank]`. BM25 ищет по словам, dense — по эмбеддингам `bge-m3`, hybrid объединяет top‑100 обоих ретриверов через RRF (k = 60). Реранкер MiniLM переупорядочивает 50 кандидатов. [Конфигурация моделей](../config.yaml) · [Реализация поиска](../src/arag/retrievers.py)

| Запрос | Что получает ретривер |
|---|---|
| `last` | Текущий вопрос пользователя |
| `user_concat` | До трёх последних реплик пользователя |
| `llm_rewrite` | Самостоятельный вопрос, сформированный одним вызовом LLM с историей |
| `chiq` | Запрос с уточнённым контекстом, см. CHIQ-AD ниже |
| `gold_rewrite` | Формулировку человека для сравнения на MTRAG. В загружаемом файле MTRAG-UN это поле пустое |

## CHIQ-AD (бейзлайн из плана)

Модель `qwen3.8` проверяет смену темы, уточняет вопрос и последний ответ, строит псевдоответ и при продолжении темы суммирует историю. Для поиска используются переписанный запрос, уточнённый вопрос и допустимый псевдоответ. Реранкер получает только переписанный запрос. В нашей реализации ответы в истории для CHIQ ограничены 600 символами, псевдоответ-отказ отбрасывается. [Реализация](../src/arag/queries.py) · [Статья CHIQ](https://aclanthology.org/2024.emnlp-main.135/)

## Роутеры (этап 4)

| Система | Что определяет выбор стратегии |
|---|---|
| `fixed` | Одна стратегия для всех ходов. Общая база для парных тестов — `llm_rewrite:dense+rerank` |
| `rule` | Текущий вопрос и наличие истории определяют необходимость переписывания. Поиск всегда dense с реранкером |
| `llm_nohist` | По текущему вопросу LLM выбирает ретривер и необходимость реранкинга |
| `llm_nohist_rewrite` / `llm_hist` | Одинаковые модель, инструкция и действия, включая переписывание. У первого поле истории пустое, у второго содержит до шести реплик |
| `adaptive_rag` | Классификатор выбирает один из трёх уровней по эмбеддингу текущего вопроса |

В контроле RQ2 меняется только история на входе роутера. Переписыватель при его вызове и генератор получают историю в обоих вариантах. [Парное сравнение](results/mtragun.md#контрольное-сравнение-для-rq2)

## Adaptive-RAG (бейзлайн из плана)

Локальная адаптация использует три уровня: dense, dense с реранкером, dense с переписыванием и реранкером. Обучающая метка — самый простой уровень с максимальным nDCG@5. В обучение входят запросы, где хотя бы один уровень достиг ненулевого результата. Логистическая регрессия (C = 1) использует эмбеддинг текущего вопроса. При кросс-валидации GroupKFold делит диалоги на пять фолдов.

В варианте `adaptive_rag_from_mtrag` обучение проводится на MTRAG. Из оценки на MTRAG-UN исключаются диалоги с общим ID или совпадающей после нормализации начальной репликой в исходной выборке. [Реализация](../src/arag/routers.py) · [Результаты переноса](results/mtragun.md#перенос-adaptive-rag-с-mtrag)

## Оракул

Для каждого хода оракул берёт стратегию с максимальным nDCG@5 по qrels. При равенстве используется заданный в CLI порядок по стоимости. Вариант `oracle_cheap` допускает отставание в пределах заданного допуска. Человеческие формулировки исключены из обоих вариантов. Задержка и токены относятся к выбранным стратегиям.

Строка оракула в таблице MTRAG получена по 18 конфигурациям из режимов `last`, `user_concat` и `llm_rewrite`. На MTRAG-UN оракул выбирает из 12 комбинаций `last` и `llm_rewrite`. В сравнении RQ1 набор из 12 действий одинаков для обоих датасетов. [Расчёт оракула](../src/arag/cli.py)

## Метрики

Recall@k измеряет долю размеченных релевантных пассажей в первых k результатах. nDCG@k учитывает их порядок. Обе метрики усредняются по ходам при k = 1, 3, 5, 10. Задержка поиска включает роутинг, формирование запроса, эмбеддинг, поиск и реранкинг. README показывает среднее и p95 по временам сохранённых прогонов. При попадании в кэш используется записанное время исходного вызова.

LLM-токены поиска включают вход и выход переписывателя и LLM-роутера. Системный расход дополнительно включает генератор. Итог округляется после сложения. Отдельно учитываются токены судьи и число обработанных пар реранкера. [Метрики поиска](../src/arag/metrics.py)

## Качество ответов и LLM-as-a-Judge

Генератор `gemma-4-26B-A4B-it` видит последние шесть реплик и пять найденных пассажей, каждый до 1500 символов. Судья `qwen3.8` получает тот же контекст, ответ и человеческий эталон. По шкале 1–5 он оценивает правильность относительно эталона (Correctness), обоснованность пассажами (Faithfulness) и полноту покрытия эталона (Completeness). Отказ получает 5 по Faithfulness, поэтому этот критерий рассматривается вместе с долей отказов.

Оценки судьи усредняются по валидным ответам (`judged`), токены и доля отказов — по всем ответам (`n`). Калибровка v2 на 477 ответах MTRAG дала корреляцию Спирмена 0.56 с человеческими оценками Faithfulness и 0.63 на 318 ответах без эталонов. [Промпты и проверка оценок](../src/arag/generation.py) · [Калибровка](results/judge_calibration_qwen_v2.md)

## Значимость

Сравниваются только общие ID ходов. Парный bootstrap по диалогам (10 000 выборок) даёт 95% доверительный интервал для разности средних. Двусторонний рандомизационный тест меняет знак всех разностей одного диалога вместе. Для сравнений с базой поправка Холма применяется отдельно по каждой метрике ко всем системам в соответствующей сводке. Для заранее выбранной пары RQ2 приводятся исходные p-значения. [Реализация тестов](../src/arag/stats.py)

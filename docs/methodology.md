# Методика

## Исследовательские вопросы

- **RQ1.** Есть ли смысл выбирать стратегию retrieval для каждого запроса отдельно? Оценивается разрывом между лучшей фиксированной стратегией и оракулом.
- **RQ2.** Помогает ли роутеру история диалога? Сравниваются роутеры с историей и без неё при прочих равных.
- **RQ3.** Какой компромисс качество / стоимость даёт адаптивный роутер? Оценивается по Pareto-кривой, где стоимость — latency и LLM-токены.

## Данные

MTRAG (IBM, `data/mt-rag-benchmark`), часть `mtrag-human`: 842 задачи, 110 диалогов, 4 домена (clapnq — Википедия, cloud — документация IBM Cloud, fiqa — финансовый форум, govt — сайты госорганов США).

- **Задача** — один ход пользователя вместе со всей предыдущей историей диалога (`Task.turns`). Последняя реплика — текущий вопрос.
- **qrels** есть у 777 задач. У UNANSWERABLE и CONVERSATIONAL задач их нет, поэтому оценка retrieval идёт только на ANSWERABLE и PARTIAL.
- **Human rewrite** (`rewritten_query`) — самостоятельная формулировка вопроса, написанная человеком. Есть у всех later-задач с qrels, на первом ходе отсутствует (там он не нужен).
- **Корпуса** — пассажи по 512 токенов с перекрытием 100. Их id совпадают с qrels.

## Стратегии

Стратегия записывается как `<query>:<retriever>[+rerank]`.

| Часть | Значения |
|---|---|
| query | `last` — последний вопрос как есть; `user_concat` — три последние реплики пользователя через пробел; `gold_rewrite` — human rewrite; `llm_rewrite` — переписывание LLM по истории |
| retriever | `bm25` (bm25s, стемминг, стоп-слова); `dense` (bge-base-en-v1.5); `hybrid` — RRF по bm25 и dense, k=60 |
| `+rerank` | cross-encoder bge-reranker-v2-m3 по top-50 кандидатам |

**Реализуемая (deployable) стратегия** — любая, кроме `gold_rewrite:*`. Human rewrite на инференсе недоступен, поэтому `gold_rewrite` — это только потолок для любых методов переписывания запроса.

**Стоимость стратегии** (`cost_rank` в `cli.py`) — условный ранг для разрешения ничьих: `llm_rewrite` = 3, `dense` = 1, `hybrid` = 1.5, `rerank` = 2, остальное 0. Реальная стоимость (latency, токены, пары для reranker) пишется в каждый run.

## Оракул

Для каждого запроса берётся лучшая по метрике (`ndcg_cut_5`) стратегия из уже посчитанных runs.

| Вариант | Поле в `runs/<ds>_oracle.jsonl` | Смысл |
|---|---|---|
| Реализуемый | `best` | Лучшая стратегия без `gold_rewrite`, при ничьей — более дешёвая. **Это разметка для обучения роутера.** |
| Cost-aware | `best_cheap` | Самая дешёвая стратегия, у которой метрика не ниже `best − eps` (`--eps`, по умолчанию 0.05). Разметка для роутера, который экономит ресурсы. |
| С gold | `best_with_gold` | Лучшая среди всех стратегий, включая `gold_rewrite`. Только верхняя граница. |

**Unsolvable** — запрос, на котором у всех стратегий метрика равна 0. Для такого запроса роутеру нечему учиться, и при обучении его стоит исключать или считать отдельно.

## Метрики

- **Retrieval**: Recall@k и nDCG@k, k ∈ {1, 3, 5, 10}, считаются через pytrec_eval так же, как в официальном скрипте MTRAG. Основная метрика — nDCG@5.
- **Стоимость**: latency по этапам (query, retrieve, rerank, router) в мс, LLM-токены (prompt + completion), число пар для reranker.
- **Ответы** (позже): correctness, faithfulness, completeness по шкале 1–5 от LLM-судьи, который предварительно калибруется на human-оценках MTRAG.

## Срезы

- `first_turn` / `later_turns` — номер хода пользователя: 1 или больше 1. Основной срез — `later_turns`, потому что на первом ходе история пуста и все query modes совпадают.
- По меткам MTRAG: домен, `Multi-Turn` (Follow-up / Clarification), `Answerability`, `Question Type`.
- `dependent` — эвристика RuleRouter: в последующем ходе есть местоимение или анафора, вопрос короче 4 слов или нет вопросительной формы.

## Значимость

`arag significance` сравнивает каждую систему с baseline по одним и тем же запросам:

- **Парный bootstrap** (10 000 ресэмплов запросов) даёт Δ среднего и 95% доверительный интервал.
- **Парный рандомизационный тест** (случайно меняем местами a и b внутри пары) даёт двусторонний p-value.
- **Поправка Холма–Бонферрони** применяется ко всем сравнениям в одной таблице.

Разница считается значимой, если `p_holm < 0.05` и доверительный интервал не содержит 0.

## Обучаемый роутер (план)

Разбиение train/test **только по диалогам** (`GroupKFold` по `conversation_id`, это часть `task_id` до `<::>`). Ходы одного диалога очень похожи, и случайное разбиение по задачам даст утечку.

## Показатели в анализе rewrite (`arag analyze`, раздел 2)

Считаются по контентным токенам: нижний регистр, без стоп-слов и вопросительных слов.

- **Jaccard** — пересечение токенов последнего вопроса и rewrite, делённое на их объединение.
- **Дефицит** — доля токенов rewrite, которых нет в последнем вопросе. Показывает, сколько контекста человек «дописал».
- **Недостающие токены в истории** — какую долю дефицита в принципе можно найти в предыдущих репликах: во всех или только в репликах пользователя.

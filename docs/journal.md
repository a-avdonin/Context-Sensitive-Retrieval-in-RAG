## 2026-11-05 — Анализ данных и BM25-бейзлайнов

**Что сделано**
- Добавлена команда `arag analyze` ([src/arag/analysis.py](../src/arag/analysis.py)). Она строит markdown-отчёт: состав датасета, сравнение последнего вопроса с human rewrite, качество стратегий по срезам, оракул, анализ того, когда rewrite помогает.
- Отчёт по трём BM25-стратегиям на MTRAG (777 задач, 4 домена): [results/mtrag_bm25_analysis.md](results/mtrag_bm25_analysis.md).

**Результаты** (nDCG@5)

1. **Качество падает с номером хода.** На первом ходе 0.335, на 6+ ходе 0.157 у `last`. 35% задач приходятся на 6+ ход, так что многоходовость — основная сложность датасета.
2. **Human rewrite помогает умеренно и не везде.** Для последующих ходов в среднем +0.025 (значимо, p_holm = 0.014). У 69% запросов ничья: обычно обе стратегии дают 0, потому что BM25 ничего не находит.
3. **Выигрыш от rewrite монотонно растёт с дефицитом контекста.** Если rewrite почти не добавляет слов к вопросу, Δ = −0.005. Если вопросу не хватает 2/3 слов rewrite и больше, Δ = +0.077, а nDCG у `last` 0.081 против 0.158 у gold. Именно эту величину роутер должен научиться предсказывать без gold.
4. **Clarification выигрывает от rewrite сильнее Follow-up**: +0.075 против +0.016. Метка `Multi-Turn` на инференсе недоступна, но её можно предсказывать как вспомогательную задачу.
5. **Keyword-вопросы от rewrite проигрывают**: −0.057, 7 побед против 12 поражений. Composite тоже проигрывают (−0.022). Значит, переписывать всегда — плохая стратегия. Это аргумент в пользу роутера.
6. **Эвристика `dependent` из RuleRouter даёт слабый, но правильный сигнал**: Δ от rewrite +0.035 у зависимых вопросов против +0.012 у самостоятельных.
7. **Склейка реплик пользователя (`user_concat`) работает только на 2-м ходе.** Там она равна gold (0.277 против 0.278), а дальше хуже `last`: тема диалога смещается, и старые реплики добавляют шум. Окно истории надо выбирать адаптивно.
8. **Только 54% недостающих слов есть в истории, и лишь 33% — в репликах пользователя.** Значит, ответы агента — важный источник контекста. `user_concat` их не видит, `llm_rewrite` видит.
9. **BM25 слишком слаб для разметки роутера.** У 56% запросов ни одна BM25-стратегия ничего не находит в top-5 (в cloud и fiqa 62–67%). Разметку оракула для обучения строить только после dense, hybrid и reranker.

**Решения**
- Признаки для будущего роутера: оценка дефицита контекста (доля слов вопроса, отсутствующих в истории, длина, местоимения), номер хода, тип вопроса (keyword или полное предложение), лексическое пересечение с последней репликой агента.
- Срез `later_turns` считать основным в отчёте. Первый ход приводить отдельно.

**Что дальше:** dense, hybrid и reranker (нужен GPU или сервер); каркас обучаемого роутера на признаках.

## 2026-11-05 — Подготовка репозитория

**Что сделано** (коммит `2a4c887`, ветка `chore/prepare-repo`)
- В `.gitignore` добавлены `data/`, `runs/`, `cache/`. Создан `.env.example` (`LLM_BASE_URL`, `LLM_API_KEY`).
- Окружение: venv на Python 3.10, `pip install -e ".[dev]"` без torch. Тяжёлые модели локально не запускаем, только на сервере.
- **Оракул исправлен.** Раньше в разметку попадал `gold_rewrite`, который на инференсе недоступен, и верхняя граница была завышена. Теперь считаются три варианта: реализуемый, cost-aware и с gold (см. methodology).
- Добавлена команда `arag significance`: парный bootstrap, рандомизационный тест, поправка Холма ([src/arag/stats.py](../src/arag/stats.py)).
- Тесты на оракул и статистику.

**Проверка:** данные MTRAG скачаны (530 МБ), прогнаны `last`, `user_concat`, `gold_rewrite` × `bm25`. Цифры из README воспроизводятся: на fiqa+govt, последующих ходах (n = 332) R@5 = 0.225 у gold и 0.185 у last.

| | nDCG@5, все 777 задач |
|---|---|
| лучшая фиксированная (`last:bm25`) | 0.197 |
| оракул, реализуемый | 0.247 |
| оракул с `gold_rewrite` | 0.285 |

Значимость относительно `last:bm25`: `gold_rewrite` +0.022 [0.007; 0.037], p_holm = 0.01; `user_concat` −0.019 [−0.037; −0.002], p_holm = 0.03.

**Ограничения:** пока нет доступа к LLM API и GPU. Без них недоступны `dense`, `hybrid`, `+rerank`, `llm_rewrite`, LLM-роутеры и судья.

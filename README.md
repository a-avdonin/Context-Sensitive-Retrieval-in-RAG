# Context-Sensitive Retrieval in Retrieval-Augmented Language Models

Индустриальный проект НИР ИТМО. Сравниваем фиксированный поиск с роутерами, которые для каждого вопроса выбирают способ формирования запроса, ретривер и необходимость реранкинга. Эксперименты проведены на MTRAG и MTRAG-UN.

## Подходы и протокол

- **Фиксированные бейзлайны.** Sparse-поиск BM25, dense-поиск по эмбеддингам, hybrid с объединением результатов BM25 и dense через Reciprocal Rank Fusion (RRF), повторное ранжирование cross-encoder. Сравниваем поиск по последней реплике с однократным LLM-переписыванием по истории и локальной реализацией CHIQ-AD, которая сначала уточняет контекст диалога. [Методика](docs/methodology.md#стратегии) · [Статья CHIQ](https://aclanthology.org/2024.emnlp-main.135/)
- **Адаптация.** В нашем варианте Adaptive-RAG классификатор по текущему вопросу выбирает между dense, dense с реранкером и dense с переписыванием и реранкером. `rule` использует эвристики по вопросу и наличию истории для решения о переписывании, сохраняя dense с реранкером. LLM-роутеры могут переключать ретривер и реранкер, а в конфигурациях с действием rewrite — и переписывание. Оракул выбирает стратегию по разметке для каждого запроса и даёт верхнюю границу nDCG@5 среди этих стратегий. [Статья Adaptive-RAG](https://aclanthology.org/2024.naacl-long.389/) · [Методика роутинга](docs/methodology.md#роутеры-этап-4)
- **Связь с SemEval-2026 Task 8.** Ближайший ориентир к нашему фиксированному пайплайну — Sifei, где также сочетаются переписывание, hybrid и cross-encoder. В обзоре рассмотрены и другие варианты: AILS-NTUA объединяет несколько переформулировок через RRF, uva-irlab-conv сочетает обучаемый sparse-поиск и listwise-реранкер, H-RAG ищет по дочерним фрагментам и их родительским документам. Их статьи описывают результаты команд в протоколе MTRAGEval. Таблицы ниже содержат метрики наших реализаций. [MTRAGEval](https://aclanthology.org/2026.semeval-1.447/) · [Sifei](https://aclanthology.org/2026.semeval-1.32/) · [AILS-NTUA](https://aclanthology.org/2026.semeval-1.175/) · [uva-irlab-conv](https://aclanthology.org/2026.semeval-1.373/) · [H-RAG](https://aclanthology.org/2026.semeval-1.155/)

Срез для обеих таблиц — последующие ходы с разметкой релевантных пассажей (qrels). Recall и nDCG приведены в порядке k = 1, 3, 5, 10. Correctness, Faithfulness и Completeness оценены по шкале 1–5 лабораторным LLM-судьёй. Задержка поиска включает роутинг, переписывание, эмбеддинг, поиск и реранкинг. Указаны среднее и 95-й перцентиль (p95) по сохранённым замерам, включая исходные времена вызовов из кэша. Токены поиска относятся к переписыванию и роутингу. Токены системы дополнительно включают генерацию ответа. LLM-судья учитывается отдельно как стоимость оценки. [Методика оценки](docs/methodology.md#метрики)

## Почему результаты различаются

Сравниваем один и тот же `llm_rewrite:dense+rerank` на четырёх общих корпусах. На последующих ходах nDCG@5 растёт с 0.4160 на MTRAG до 0.4933 на MTRAG-UN, Recall@5 — с 0.4471 до 0.5455, Correctness — с 3.529 до 3.806. Числа ниже рассчитаны по тем же срезам, что и таблицы.

- **ClapNQ (Википедия) и Cloud (документация IBM).** Это два крупнейших прироста nDCG@5 у общей dense-базы. ClapNQ растёт с 0.486 до 0.636 (180 и 74 хода), Cloud — с 0.393 до 0.488 (163 и 81). На Cloud у фиксированного hybrid с переписыванием среднее выше, чем у dense с тем же переписыванием и реранкером: 0.409 против 0.393 на MTRAG и 0.533 против 0.488 на MTRAG-UN.
- **FiQA (финансовый форум).** Самые низкие nDCG@5 и Correctness у общей базы на обоих датасетах. Поиск снижается с 0.310 до 0.298 (156 и 53 хода), Correctness — с 3.282 до 3.245. Примерно на 40% ходов в top‑5 нет ни одного размеченного релевантного пассажа на каждом датасете. На MTRAG-UN `rule` даёт 0.335 nDCG@5 на FiQA, но средний Correctness почти тот же (3.226 против 3.245).
- **Govt (сайты госорганов США).** У общей базы nDCG@5 растёт с 0.459 до 0.496 (176 и 101 ход). Здесь самый большой провал `rule` относительно dense-базы на MTRAG (0.423 против 0.459). На MTRAG-UN наибольшее падение у `rule` приходится на ClapNQ (0.597 против 0.636), а у Adaptive-RAG — на Cloud (0.404 против 0.488). Доменные разницы описательные.
- **Состав оценочного среза.** MTRAG-UN выбирает репрезентативный ход из каждого диалога, отдавая приоритет сложным случаям. Из 507 доступных в наших четырёх доменах задач 175 остаются за пределами оценки по qrels (97 `UNANSWERABLE` и 78 `UNDERSPECIFIED`). Если перевзвесить MTRAG по долям сочетаний домена и номера хода (2, 3, 4, 5, 6+), наблюдаемым на MTRAG-UN, его nDCG@5 поднимается с 0.4160 до 0.4274 при 0.4933 на MTRAG-UN. Значит, состав по доменам и номерам ходов объясняет лишь часть разницы. В сравниваемых срезах различаются сами вопросы и число размеченных релевантных пассажей на ход (в среднем 2.80 и 2.54). У общей базы доля ходов без релевантного пассажа в top‑5 падает с 31.3% до 22.3%. При наличии такого пассажа Correctness выше на обоих срезах (4.05 против 2.38 на MTRAG и 4.15 против 2.62 на MTRAG-UN). [Датасет MTRAG-UN](https://aclanthology.org/2026.findings-acl.503/) · [Методика](docs/methodology.md#данные)
- **Задержка.** Среднее время переписывания у общей dense-базы в сохранённых запусках составляет 1.10 с на MTRAG и 26.24 с на MTRAG-UN. Именно этот этап даёт основную разницу в задержке поиска. Редкие долгие вызовы увеличивают среднее, поэтому для некоторых систем среднее выше p95. Для сравнения скорости нужен повторный замер в одинаковых условиях. [Условия замера](docs/reproduction.md#файлы-прогонов-и-повторный-запуск)

## Выводы по исследовательским вопросам

- **RQ1. Запас для адаптации.** Если оракул выбирает из одних и тех же 12 конфигураций, его nDCG@5 составляет 0.597 на MTRAG и 0.697 на MTRAG-UN. Лучшие фиксированные пайплайны дают 0.416 и 0.509. Ни один из протестированных роутеров не сокращает этот разрыв относительно лучших фиксированных конфигураций по среднему nDCG@5. [Анализ оракула на MTRAG](docs/results/mtrag_analysis.md#4-оракул) · [Методика](docs/methodology.md#оракул)
- **RQ2. История на входе роутера.** Фиксированный `llm_rewrite:dense+rerank` даёт 0.4933 nDCG@5 на MTRAG-UN, `llm_nohist_rewrite` — 0.4311, `llm_hist` — 0.4460. У двух LLM-роутеров совпадают модель, инструкция и действия. Доступ к истории повышает средние nDCG@5 на 0.0149 и Correctness на 0.0453, обе разницы статистически незначимы. Расход токенов увеличивается на 18%. У исходного `llm_nohist`, который использовался на MTRAG, отсутствует действие переписывания, поэтому его сравнение с `llm_hist` измеряет разницу между конфигурациями целиком. [Контрольное сравнение](docs/results/mtragun.md#контрольное-сравнение-для-rq2)
- **RQ3. Качество и стоимость.** `rule` экономит около 8% токенов системы на обоих датасетах. На MTRAG снижение nDCG@5 на 0.023 статистически значимо, на MTRAG-UN снижение на 0.016 относительно dense-базы статистически незначимо. Разница в Correctness статистически незначима на обоих датасетах. Adaptive-RAG с кросс-валидацией экономит 13% токенов на MTRAG и 11% на MTRAG-UN, применяя реранкер на 59% и 53% ходов. Faithfulness почти достигает потолка шкалы, в том числе потому, что отказ получает 5 по этому критерию. [MTRAG](docs/results/mtrag_answers.md) · [MTRAG-UN](docs/results/mtragun.md)
- **Реранкинг и переписывание.** На поиске по последней реплике добавление реранкера к dense повышает nDCG@5 с 0.307 до 0.349 на MTRAG и с 0.351 до 0.410 на MTRAG-UN. Correctness тоже растёт, с 3.223 до 3.283 и с 3.301 до 3.484 соответственно. CHIQ-AD требует на 82% и 73% больше токенов системы, чем однократное переписывание с теми же dense и реранкером. Различия по nDCG@5 и Correctness статистически незначимы на обоих датасетах. На MTRAG-UN средний nDCG@5 у CHIQ-AD выше на FiQA (0.347 против 0.298 у однократного переписывания), а на Cloud ниже (0.433 против 0.488). Доменные разницы описательные. [MTRAG](docs/results/mtrag_answers.md) · [Дополнительное сравнение на MTRAG-UN](docs/results/mtragun.md#дополнительные-прогоны)
- **Дальнейшая работа.** Разобрать промахи на FiQA, проверить включение реранкера и истории при ограниченном бюджете и оценить решения об отказе или уточнении на `UNANSWERABLE` и `UNDERSPECIFIED`. Лёгкий TF-IDF + SVM, гейт поиска по неуверенности модели, адаптивное взвешивание BM25 и dense и перенос на CORAL — отдельные кандидаты из дизайна и обзоров. Численные результаты в этом README относятся к сохранённым прогонам на MTRAG и MTRAG-UN.

## Как повторить

Для прогона BM25 достаточно Python 3.10+ и данных. Лабораторный API для этого прогона не нужен. Команды выполняются из корня проекта.

```bash
python3 -m venv venv
source venv/bin/activate
python -m pip install -e ".[dev]"
./scripts/download_data.sh
arag run --dataset mtrag --strategies last:bm25
arag eval --dataset mtrag --slice later_turns
```

Для полных прогонов из таблиц понадобятся зависимости `.[neural,dev]` и доступ к моделям лаборатории через LiteLLM. [Команды полных прогонов MTRAG и MTRAG-UN](docs/reproduction.md)
